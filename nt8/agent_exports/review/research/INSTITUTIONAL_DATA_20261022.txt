1. DATA STORAGE AND QUALITY
=====================================================================================================================
1.1 What institutions do
- Immutable raw layer + regenerable derived layers. Raw vendor/exchange files are kept byte-for-byte as received (never
  edited), every derived file (bars, features, caches) is rebuilt by versioned code. Two Sigma (primary, "Treating Data
  as Code at Two Sigma", E. Baram, 2025-11-13): datasets AND the processing code are versioned so any past state can be
  replayed; transformations are version-controlled and run automated data-quality tests; statistical anomaly detection
  stops bad data before it reaches users; lineage of pipeline dependencies is tracked; producer/consumer "data
  contracts" prevent silent schema changes.
- Point-in-time ("as-of") storage: keep both the event time and the time you knew it, and never overwrite history with
  revised data; research uses only what was known at decision time. Databento's records carry ts_event (exchange) and
  ts_recv (capture) (primary docs); its OHLCV ts_event is the START of the interval and empty intervals print no bar
  (primary docs) - this setup already shifts Databento bars to close time (+1 min in convert.py).
- Vendor condition metadata: Databento exposes per-day dataset condition (available / degraded / pending / missing,
  with last_modified_date) via metadata.get_dataset_condition (primary API reference). Whether the call is billed is not
  stated on that page (I believe metadata calls are free; not confirmed).
- Checksums/manifests: vendors ship SHA-256 manifests (Databento batch manifest.json: name, size, SHA-256 of every file,
  primary docs); the archival standard for "bag of files + manifest" is BagIt (IETF RFC 8493). Desks verify on ingest
  and periodically ("fixity").
- Production pipelines with automatic spike checks: Rob Carver's open-source pysystemtrade (ex-Man AHL PM; primary
  docs, production.md) refuses to write a new futures price if it moves more than max_price_spike x the average absolute
  daily change (example 8x), emails the operator and waits for a manual check. Daily database dumps / CSV backups are
  part of its scheduled run_backups process; a scheduled failover to a backup machine is recommended.
- Backups: 3-2-1 (CISA / US-CERT paper "Data Backup Options", Ruggiero & Heckathorn, 2012, primary): 3 copies (1 primary
  + 2 backups), on 2 different media types, 1 copy offsite. Vendors add "1 immutable/offline copy, 0 restore errors"
  (3-2-1-1-0; vendor blogs, secondary). Sync is not backup: OneDrive personal keeps deleted items 30 days and the last 25
  versions of a file (Microsoft support, primary) - deletions/corruption otherwise propagate.
- Tick-data cleaning (academic standard): Barndorff-Nielsen, Hansen, Lunde & Shephard (2009, Econometrics Journal 12,
  "Realized kernels in practice: trades and quotes") and Brownlees & Gallo (2006, CSDA 51). Rules as implemented in the
  R highfrequency package (secondary, cites both): drop zero prices; one exchange only; merge same-timestamp records by
  median; drop quotes whose spread > 50 x the day's median spread (rmLargeSpread default 50); flag prices that sit more
  than maxi median-absolute-deviations from a rolling CENTRED median that excludes the observation; the package's
  "advanced" variant also compares with the forward and backward medians so genuine jumps are NOT deleted; trades
  outside [bid - spread, ask + spread] are dropped (T4-type rule; exact paper wording not retrieved).
- Exchange semantics matter for dedup and aggressor side (CME MDP 3.0 docs, primary): Trade Summary tag 5797
  AggressorSide 0 = no aggressor, 1 = buy, 2 = sell; "no aggressor" occurs at market open, after pre-open/pause, and when
  a customer order trades against a Globex-implied price; one Trade Summary groups all resting fills of one aggressor
  order. So two identical prints at the same millisecond can be two real trades - dedup only on sequence numbers.
- Formats: columnar compressed files (Parquet + zstd) for derived data; keep the vendor's native compressed format
  (DBN .dbn.zst) as the raw layer. (General practice; pysystemtrade supports Parquet - primary docs.)

2. LIVE-vs-BACKTEST RECONCILIATION AND "IS IT BROKEN?"
=====================================================================================================================
2.1 What institutions do
- Shadow/out-of-sample backtest run in parallel with live and compared daily. QuantConnect (primary docs) runs an OOS
  backtest beside every live deployment and lists the usual causes of divergence: data-provider differences, look-ahead
  in custom data, discrete time-step effects, data corrections after the fact, fee/slippage/fill model errors, stale or
  limit fills, live and backtest not sharing start date/holdings, non-stateful restarts, pre-existing holdings.
- Implementation shortfall (Perold 1988, JPM 14(3); paywalled, described by secondary sources): paper portfolio return
  minus real portfolio return, decomposed into delay cost, trading cost (spread + impact), opportunity cost of unfilled
  trades, and fees. AQR's Frazzini-Israel-Moskowitz "Trading Costs" (2018, SSRN 3229719, primary abstract) measured
  costs on $1.7 trillion of their own executions - desks measure their own costs rather than assume them.
- pysystemtrade (primary docs) - a public template of a desk's daily reports: Trade report splits slippage into delay
  (generation -> submission -> fill), bid/ask (mid vs side price) and execution (side vs fill), in ticks, vol units and
  money; Costs report checks the configured cost against the worst of three measured spread estimates over 250 days;
  Reconcile report checks optimal vs actual position, instrument vs contract positions, and broker vs database
  positions, and locks an instrument on a mismatch; Status report tracks process run times and last data updates.
- Model-risk governance (Federal Reserve / OCC SR 11-7, 2011, primary letter; detail via secondary summaries): conceptual
  soundness, ongoing monitoring (process verification, benchmarking) and outcomes analysis (back-testing outputs against
  actual outcomes), effort proportional to model importance, documentation and inventory.
- Decay is the base rate: post-publication returns of 97 anomalies fell 58% (McLean & Pontiff 2016 JF, 26% out of sample
  + publication effect; primary summary); CFM's Falck-Rej-Thesmar (2022, Quantitative Finance 22(11)) find out-of-sample
  performance of published anomalies is ~50% of in-sample, decay rising ~5 pp per year of publication year and ~15% of
  variance explained by overfitting proxies. Bank "alternative beta" indices: median backtest Sharpe 1.20 vs 0.31 live
  (Suhonen-Lennkh-Perez 2017 JPM; secondary summaries). Quantopian, 888 algorithms: backtest Sharpe had R^2 < 0.025 for
  out-of-sample Sharpe; more backtesting -> bigger gap (Wiecki et al. 2016; abstract).
- Deciding a strategy is broken:
  * Drawdown-based limits sized from the Sharpe ratio: Bailey & Lopez de Prado, "Stop-outs under serial correlation and
    the 'triple penance' rule" (J. Risk 2015): under IID normal returns, recovery takes on average ~3x the time spent
    reaching the drawdown quantile; firms rationally give higher-Sharpe managers looser stop-outs; serial correlation
    changes this (abstract + secondary).
  * CFM (Rej, Seager, Bouchaud 2017, "You are in a drawdown. When should you start worrying?", arXiv 1707.01457,
    primary): with P&L as drifted Brownian motion (10-year horizon), the 5% thresholds are about
    length l5 ~ 2.14 / SR^2 years and depth d5 ~ 1.50 / SR annual-vol units; beyond them: bad luck (5%), overestimated
    SR, or a model that understates fat tails/autocorrelation - the test cannot separate the first two, so it is a
    precautionary trigger for review, plus a way to re-estimate SR from the observed drawdown.
  * Sequential tests: CUSUM (Page 1954, Biometrika 41), SPRT (Wald 1945, Ann. Math. Stat. 16), Bayesian online
    changepoint detection (Adams & MacKay 2007, arXiv 0710.3742, primary: exact online posterior of the "run length"
    since the last change); Lopez de Prado's AFML has a chapter on structural-break tests (CUSUM, Chow-type, SADF)
    (chapter list not verifiable from the publisher page - see s.6).
  * Probabilistic / minimum track record: PSR and MinTRL (Bailey & Lopez de Prado 2012, J. Risk; formula reproduced in
    Lopez de Prado's "10 Reasons Most ML Funds Fail", 2018, primary):
      PSR(SR*) = Phi( (SR - SR*) sqrt(T-1) / sqrt(1 - g3 SR + (g4-1)/4 SR^2) )
      MinTRL   = 1 + (1 - g3 SR + (g4-1)/4 SR^2) (z_alpha / (SR - SR*))^2   (per-period SR, g3 skew, g4 kurtosis)
  * Numeric stop-out rules at multi-manager funds (e.g. capital halved at -5%, stop at -7.5%) are widely reported in the
    press; I found no primary source and do not rely on them.

2.2 Where this setup stands
 Decisions: recomputed every day (0 mismatches). Code: Analyzer parity. Fills: sequential cost alarm vs 1.5 ticks.
 Edge: CUSUM (681 / 1,297 bp). P&L: 20-session 90% band as share of notional. Paper test of 10 variants.
 Gaps: no per-fill shortfall decomposition yet (recorder pending F5; Sim101 fills are internal, so real numbers start on

2.3 Numbers for this strategy (computed today, read-only)
 Input: s1_reference_trades_ntbars_v3.csv, 1,666 trades 2019-05-28 .. 2026-10, $2/point, minus 1 tick/side ($1) and
 $1 RT; 1,927 weekdays with zero on no-trade days (holidays counted as zero days: slight understatement of SR).
   mean $12.57/day, sd $173.05/day -> $3,169/yr, annual sd $2,747, annual SR 1.15; skew +4.0, kurtosis 57 (fat tails).
   PSR(SR*=0) over the full 2019-26 sample = 0.9998.
   MinTRL at 95% (SR*=0):  true SR 1.15 -> 402 sessions (1.6 yr); SR 0.87 -> 750 (3.0 yr); SR 0.58 -> 1,789 (7.1 yr).
   SPRT (alpha = beta = 5%, normal approx): "no edge" vs "backtest edge" ~1,115 sessions (4.4 yr);
                                            "half edge" vs "full edge" ~4,461 sessions (17.7 yr).
   Rej et al. 5% thresholds at SR 1.15: drawdown length ~1.6 yr; depth ~1.30 x $2,747 = ~$3,600 per micro (2019-26
   prices). If SR were 0.58: length ~6.4 yr, depth ~2.6 x vol. IID day-bootstrap max drawdown: 63 sessions p95 $1,955
   (p99 $2,561); 252 sessions p95 $3,397 (p99 $4,464). Fat tails (kurtosis 57) mean the Brownian thresholds can be too
   tight on depth - use the larger of the two.
   Lag-1 autocorrelation of P&L: daily -0.056 (2 s.e. 0.046), weekly -0.111 (0.102), monthly -0.140 (0.211).
 Reading: a year of live trading cannot validate or reject the edge statistically; it CAN show broken mechanics in days.

2.4 What to adopt for free - concrete steps
 a) Shortfall decomposition (when TapeRecorder runs): for each order, from recorder + NT executions:
    decision price = 5-min close that triggered it; send time; ack time; mid and touch at send; fill price(s) and time.
    delay_cost = side x (mid_at_send - decision price); spread_cost = side x (touch - mid) at send;
    execution_cost = side x (fill - touch at send); fees = actual vs Bulenox rate sheet ($0.61/side).
    Report per slot (10:00 separately), per day, and cumulative vs the backtest's 1 tick/side + $1 RT. Feed the per-slot
    medians into the research cost model (one pre-registered re-run, like EXEC_PILOT/LIMIT).
 b) Daily tracking difference in dollars: live net P&L minus same-day model P&L (same bars, model costs). Break it into
    decision differences (should be 0), fill differences (a), fees, and missed/extra trades. One line in daily_review.py;
    the existing cost alarm already provides the sequential threshold.
 c) Drawdown length/depth alarm next to the CUSUM (monitor.py): WARNING at the 5% Rej-Seager-Bouchaud threshold OR the
    bootstrap p95 for the elapsed window, whichever is larger; NEEDS ATTENTION at p99. Express in share of notional so it
    survives price-level changes. Pre-register it in MONITOR_PLAN.txt (amendment) with the false-alarm rate.
 d) Write the expectations into NoiseArea_Strategy.md: the MinTRL/SPRT table above, plus a planning prior of half the
    backtest edge (Falck et al.; McLean-Pontiff) - the projections already carry an "edge halves" case ($2,400/yr).
 e) Optional, for monitoring only: Bayesian online changepoint (Adams-MacKay) on daily P&L with a Student-t likelihood;
    it gives "probability the regime changed in the last N days". Same power limits as CUSUM; adds an interpretable
    number, not new information.
 f) Once on Bulenox: weekly 3-way reconciliation - strategy trade log vs NT executions vs Bulenox/Rithmic statement
    (fills, fees, P&L); the broker statement is the book of record.

2.5 Expected benefit
 a/b: real cost numbers replace the 1-tick assumption; ~$50-150/yr per micro of model error becomes visible (10:00 alone

3. BACKTEST INTEGRITY FOR INTRADAY FUTURES

3.1 What institutions do / what the literature warns
- Count and deflate every trial: Bailey-Borwein-Lopez de Prado-Zhu, "The Probability of Backtest Overfitting" (J. Comp.
  Finance 2017; CSCV method; R package pbo); Deflated Sharpe Ratio (Bailey & Lopez de Prado 2014, JPM 40(5)); Harvey,
  Liu & Zhu (2016, RFS 29) t > 3.0 for new factors; Harvey & Liu "Backtesting" (2015, JPM 41(1)) - haircut Sharpe
  depends on the number of tests and is nonlinear: marginal Sharpe ratios are cut heavily, very high ones only
  moderately; a flat 50% haircut is "a rule, not a method" (Harvey, man.com). Lopez de Prado (2018, "10 Reasons",
  primary): ~20 iterations on the same data produce a false strategy at 5%; walk-forward tests a single path and is as
  easy to overfit as walk-backward; use many paths (CPCV) and report the number of trials. Lopez de Prado & Lewis
  (2019, Quant. Finance 19(9)): estimate the EFFECTIVE number of uncorrelated trials by clustering the trials.
  Stepwise multiple testing with bootstrap (White 2000 Reality Check; Hansen 2005 SPA; Romano & Wolf 2005 Econometrica
  73(4)) - Romano-Wolf captures the dependence between tests and is more powerful than single-step methods.
- Fills/costs: market orders pay the spread plus impact plus latency drift; queue position matters only for limit
  orders. NinjaTrader's historical fill engine (primary help): Standard resolution fills on the strategy's own bars;
  High resolution uses a finer secondary series; slippage is added per order but cannot exceed the next bar's high/low.
  The Zarattini et al. paper used $0.001/share slippage and, in its FAQ, re-ran with the Kissell I-Star impact model
  (large-cap parameters): Sharpe 1.33 -> 1.17 (primary).
- Look-ahead traps typical for this setup: bar timestamp conventions (Databento = interval start, NinjaTrader = bar
  close), daily statistics computed with the current day, VWAP including the decision bar's future ticks, holiday /
  early-close sessions, DST shifts between ET/CT/UTC, data corrected after the fact (QuantConnect list), back-adjusted
  continuous prices used where raw prices are needed.
- Roll handling: NinjaTrader merge policies (primary help): DoNotMerge = only the selected expiry, raw; MergeBackAdjusted
  = offsets back-adjust history to the next front month; MergeNonBackAdjusted = joined, raw, gaps at rolls. Rollover
  dates/offsets come from the Instruments editor. Databento continuous symbology selects contracts by calendar, volume
  or open interest without price adjustment. pysystemtrade keeps roll states (passive, force, force-outright) and
  separate "priced" and "forward" contracts. Equity-index futures roll ~8 days before third-Friday expiry by convention
  (forums; CME's own page not retrieved).
- Survivorship in futures is instrument/strategy SELECTION, not delisting: choosing the market or rule because it worked.

3.2 Where this setup stands
 Strong: parity to the dollar, two data sources, Databento start-stamp shift handled, 1 tick/side + commission, cost of
 10:00 entries measured from real trades, latency measured, early closes and DST fixed, holdout eras, Holm/Bonferroni,
 month-block bootstrap. For this strategy additive back-adjustment barely matters for the BANDS (they are ratios inside a
 14-day window), but it does matter for any absolute-price comparison - the fill-cost bug of 2026-10-19 was exactly that.

3.3 What to adopt for free
 a) Trial registry (one CSV): plan, date, family, data window, N variants, per-variant Sharpe/t, verdict. Then compute
    DSR for any future adoption at the PROGRAM level, not only inside one plan's family. Illustration for the base rule
    (2019-26, SR 1.15/yr): DSR is 0.97 if 10 near-identical alternatives were considered before choosing it (variance of
    trial Sharpe = sampling variance), 0.90 at 30, 0.72 at 150; if the trials were twice as dispersed, 0.52 at 10 and
    0.14 at 30. The answer hinges on how many published strategies were really looked at before NoiseArea was chosen and
    how dispersed their Sharpe ratios were - the registry makes this an honest number instead of a guess.
 b) Romano-Wolf stepdown (block-bootstrap, studentized) for families of correlated variants (NAVAR, DAYCAP): same
    family-wise error, more power than Holm when variants are correlated. It would not have rescued K1 (P 0.27 vs bar).
 c) Provenance stamp in every results file: git commit of the code, SHA-256 of each input data file, Python + package
    versions, data window. Makes any number re-creatable (SR 11-7 documentation; Two Sigma replayability).
 d) Slot-specific cost model: per decision time, cost = median measured spread/slippage for that slot (from the
    recorder and the purchased 10:00 trades), with a sensitivity row at 2x. One pre-registered re-run.
 e) Calendar stress list: mark CME halts and limit days (e.g. 2020-03 limit-down nights; 2025-11-28 Globex halt of ~10
    hours from a CyrusOne data-centre cooling failure; secondary press) and confirm the backtest neither trades through a
    halt nor fills at a price that did not trade. US equity-index futures limits: 7/13/20% in US hours and 7% overnight
    with a 3.5% dynamic circuit breaker since 2020-10-12 (CME FAQ; S&P products have a separate FAQ).
 f) Keep raw per-contract prices for every fill/slippage comparison; back-adjusted series only for multi-day signals.

3.4 Expected benefit
 a/c: protects against self-deception as the trial count grows (already >9,500 rules tested in the program); b: small;
 d: brings the backtest's net about $50-150/yr per micro closer to reality; e: closes a rare-event blind spot.

4. POSITION SIZING AND DRAWDOWN CONTROL (single strategy, hard drawdown limit)
=====================================================================================================================
4.1 What institutions use and the evidence
- Volatility targeting: Man AHL / Harvey et al. (2018, "The Impact of Volatility Targeting", JPM 45(1), primary): over
  60 assets 1926-2017, vol targeting raises Sharpe only for risk assets (equities, credit) via the leverage effect;
  negligible for bonds, FX, commodities; it does reduce extreme tail returns everywhere. Moreira & Muir (2017, JF) found
  in-sample alphas; Cederburg, O'Doherty, Wang & Yan (2020, JFE 138, primary abstract): across 103 equity strategies the
  feasible real-time versions generally have LOWER Sharpe and certainty-equivalent returns than unmanaged ones
  (structural instability). Momentum-specific: Barroso & Santa-Clara (2015, JFE) and Daniel & Moskowitz (2016, JFE) show
  vol scaling helps cross-sectional stock momentum because its crashes come in high-vol states - a different object
  from an intraday breakout whose bands already widen with volatility.
- The NoiseArea paper itself (Zarattini, Aziz, Barbon 2024, primary): sizing to a 2% daily vol target (14-day
  realised, leverage capped at 4x) moved Sharpe 1.24 -> 1.33 but max drawdown 12% -> 25% and vol 7.7% -> 14.3% - most of
  the gain is leverage, not risk-adjusted improvement. Consistent with this program's finding that vol sizing did not
  help (EVALVOL; EDGES3 "sizing up on high-vol days adds risk in proportion").
- Drawdown-constrained sizing: Grossman & Zhou (1993, Math. Finance 3(3)): with wealth kept above alpha x running max,
  the optimal risky exposure is proportional to the cushion (wealth - alpha x max); CPPI (Black & Perold 1992, JEDC) is
  the floor-based version. Discrete-time caveats exist (Klass & Nowicki 2005). This is the theoretical template for a
  trailing-drawdown prop account: trade size proportional to room left.
- Stop-loss / equity-curve rules: Kaminski & Lo (2014, J. Financial Markets 18): under a random walk a 0/1 stop-loss
  always lowers expected return; it adds value only with momentum (positive serial correlation) in the P&L. Carver
  (qoppac blog, 2015-11-10, random-data study, primary): equity-curve filters reduce returns for every profitable curve
  unless return autocorrelation is positive (he suggests >= ~0.2 after costs); with trend-following's negative
  autocorrelation it is "an unmitigated disaster".
- Fractional Kelly: Thorp (2006, Handbook of Asset & Liability Mgmt ch. 9, primary, eq. 7.13): betting c x Kelly, the
  probability of EVER falling to a fraction x of starting capital is x^(2/c - 1); full Kelly: P(halving) = 1/2; half
  Kelly: 1/8, at 3/4 of the growth rate. Busseti, Ryu & Boyd (2016, J. Investing, primary abstract): an explicit
  drawdown-risk constraint beats fractional Kelly at equal drawdown risk. Parameter uncertainty (SR may be half) pushes
  the right fraction lower - this program's SCALING test already found that half-Kelly fails its bar.

4.2 Evidence applied to this strategy
 NoiseArea's P&L autocorrelation is negative at every horizon measured (daily -0.056 significant; weekly -0.11;
 monthly -0.14), so by Kaminski-Lo and Carver, drawdown/equity-curve de-risking should LOWER expected return - exactly
 what DAYCAP (daily caps, stop after losses) found. Its per-trade risk already scales with volatility through the bands,
 and contract-level vol scaling was tested and did not help. Net: institutions' sizing tools offer no return gain here;
 their role is survival under a hard limit.

4.3 What could still be adopted (free)
 a) Keep sizing unchanged for Sim101 / self-funded (scaling schedule already set from simulation).
 b) For the Bulenox evaluation, one pre-registered run in the existing evalvol/biglever harness of a Grossman-Zhou style
    rule: micros = clip(floor(room_left / k), 1, 6) where room_left = equity - trailing floor and k is fixed in the plan
    (e.g. the 1-in-20 one-day loss per micro). Expected: higher survival per try, slower progress to target; whether the
    30-day pass rate rises is an open empirical question (the eval objective is pass-before-ruin within a time limit,
    not long-run growth, so theory does not settle it).
 c) If a hard limit forces a choice, prefer explicit drawdown-probability sizing (Busseti-Ryu-Boyd style, or simply
    Monte Carlo at a haircut SR) over "half Kelly" rules of thumb.

 a) Pre-trade risk controls and kill switch outside the strategy (FIA, "Best Practices for Automated Trading Risk
    Controls and System Safeguards", July 2024: max order size, intraday position limits, price tolerance,
    cancel-on-disconnect, kill switches at trader/broker/exchange level). Here: the size-aware desync guard exists; add
    (1) a hard max-position check independent of the strategy (watchdog reads account position from the heartbeat and
    alerts if > registered contracts), (2) a written kill procedure: who flattens, how (broker trade desk phone number
    on paper next to the PC), tested once. Cancel-on-disconnect only cancels orders - it does not flatten.
 b) Disaster stop (item 4 in s.0) - the position is unprotected during a PC/ISP/NinjaTrader failure.
 c) Independent monitoring channel (item 4) - the current alert path has known holes.
 d) Change management: Knight Capital (SEC press release 2013-222: $12m settlement, first Market Access Rule case; the
    SEC order cites two technology missteps and 97 automated e-mails sent to staff) is the industry's lesson on
    deployment errors and alerts nobody acts on. Here: the deployed .cs hash is recorded in CLAUDE.md; also write it into the events file
    at every strategy start, and alarm if the running hash differs from the registered one.
 e) Book-of-record reconciliation (s.2.4 f).
 f) Same-day replay through the live code: NinjaTrader's "Enable market recording for playback" (Tools > Options >
    Market Data; files in db\replay; Level II only when a DOM/L2 window is open; forum + help, primary-ish) records the
    live session so it can be replayed on the Playback connection with the exact NinjaScript - a cheap
    "same-day replay" without buying data. Sashkin's click; disk use is modest for L1 only.
 g) Expectation documents: the MinTRL/SPRT/drawdown tables in s.2.3 belong next to the strategy so a bad quarter is
    judged against them, not against feelings (Carver's argument for systematic rules; AQR/CFM drawdown papers).
 h) Instrument/strategy selection honesty: record why NQ (not SPY) and why NoiseArea (not the other published rules)
    were chosen and when - this is the "survivorship" of systematic trading and feeds the DSR (s.3.3 a).
