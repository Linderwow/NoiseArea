Data note (found before the plan was written, and the reason for its roll-window rule): the Databento files are calendar-roll
continuous (.c.0). In the last 4-5 sessions before each contract switch they hold the expiring contract, with 3-70% of the market's
volume. On all other sessions Databento and NinjaTrader volume agree exactly (median ratio 1.000), so NinjaTrader's history is
front-by-volume. Any future Databento-based volume study must handle those sessions. The rebuilt 5-minute files
(nt_analyzer_bars.csv, mnq_db_5m.csv, mnq_db_5m_2019-2026.csv, nq_2010-2019_5m.csv, about 124 MB) now sit in this folder, and
relvol_data.py rebuilds them.

If this is ever re-examined, use only data that did not exist when this file was written, and hold it to the same bar. Volume
in the opposite sense, "skip abnormally high-volume break-outs", is a new hypothesis suggested by this data. It would need its own
plan and fresh data. It is not a variant of this test, and it was not run.
